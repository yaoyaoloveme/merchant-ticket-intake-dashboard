# 每日外呼监控：天润证据修正版

入口：`http://127.0.0.1:8090/#employee`。监控只读，不自动拨号、不改派、不补写历史备注。

## 修正的问题

旧版把“看板没有登记”显示成“未外呼”，且用当前名单补判历史需外呼，不能用于考核员工。修正版取消这类结论：

- 历史需外呼以派单快照和同次天润派单备注为准，不套用当前滚动名单。
- 天润详情中的 `comments` 与操作日志是不同字段。现在直接读取前者，包含员工沟通记录和系统派单备注。
- 对应派单时间前后90秒内的系统派单备注含【需外呼】才核实提醒送达；没有匹配备注时是待核实，匹配备注无提醒时是当时未提示。
- 电话沟通证据须为明确已致电、已外呼或结构化“触达方式：电话”；计划、否定、入呼描述、提醒及自动同步模板不计。
- 原文内明确时间作为证据时间，同时保留备注保存时间。缺少明确通话时间则注明使用登记时间；跨日不把昨日通话算作今日。
- 天润备注条数和看板登记条数分列，不相加成实际拨打次数；同店关联工单也不等于逐单完成。
- 没找到或没读到记录只显示“联系情况待核实”，不能认定员工未执行。系统提醒问题与员工执行情况分开。

## 来源及边界

公司派单记录从 `172.31.61.35:8090` 既有只读接口获取；天润原始备注用本机已配置官方API只读获取。凭据不进入网页和发布包。

当前母集仍是所选日期看板派给当前在册员工的工单。非看板派单、停用员工、往日派单今日联系且不在任务列表的记录可能不在范围内，不是天润全量话单报表。备注是员工填写的证据，并非运营商话单或录音核验。

逐员请求4并发；天润备注读取6并发、65秒预算，未读完明确列为待核实。汇总缓存45秒，备注缓存120秒，保留真实读取时间，页面60秒检查刷新。数据源失败不会伪装为0；切日期/来源不沿用旧范围数字。

## 新派单提醒

【需外呼】随派单写入天润，要求员工直接在原工单备注填写电话沟通记录，不依赖看板二次登记。派单成功后只读核验提醒，单次等待最多2秒、整批等待最多6秒；超时或不匹配提示核对，不自动重派、不重发备注。核验结果保存在独立 `assignment_outbound_delivery` 表，历史派单原文不修改。

公司发布仅包含 `app.py`、`tianrun_outbound_evidence.py` 和清单。不覆盖数据库、凭据、商家名单、员工配置或其他未发布本机功能。
