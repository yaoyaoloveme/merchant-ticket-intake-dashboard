# 每日外呼监控（本机）

入口：`http://127.0.0.1:8090/#employee`，员工工单卡点页面顶部。

默认只读查询公司 Mac `172.31.61.35:8090` 的现有接口，不发布公司代码、不改派工单、不领取或保存外呼任务。需要本机能访问公司网络；可切换到本机记录，但两台机器数据不混合。

## 统计口径

- 日期使用北京时间，默认今天，可回看历史；打开今天时跨零点自动切换新日期。
- 需外呼：所选日期看板派单中有需外呼标签的工单，按工单号取当日最后一次有效派发，跨员工去重。
- 实际登记次数：仅 `action=complete`，按结果保存的北京时间归属；领取、释放、转交均不计入。
- 结果分为已接通、未接通、约定回电；约定回电不自动算作已接通。
- 同店多工单共享外呼。关联工单不等于每张都已经沟通，不可用关联工单数代替拨打次数。
- 当前既有数据是员工自行登记结果，不是天润话单/录音核验；未登记到看板的电话无法确认。

## 公司兼容读取的边界

读取 `/api/tianrun/team`，逐员读取 `/api/tianrun/team/<employee>/assignments?date=...`。
历史日期另外读取 `/api/tianrun/outbound/<shop>?date=...`，不误用派单接口附带的今天状态。

只能覆盖当前在册员工的当日派单关联店铺及接口可见任务。已停用员工、未经过看板派单、往日派单今日才联系且不在当前任务中的店铺可能遗漏。因此不能称为全公司全量电话报表。要做到全量，需要公司端增加按日期导出完整任务与结果的只读接口，或另接天润话单；此次没有改动公司端。

逐员查询使用4并发，失败只读重试一次，整体有85秒预算；剩余失败人员明确列出，统计标为已读取部分。成功结果短时缓存45秒，页面60秒检查刷新。读取失败显示错误；同范围保留旧数据时标注过期，换日期或来源不沿用旧数据。外呼记录不完整的店铺标为待核对，不误计成未联系。

## 页面使用

点击指标卡可筛选；下方可按店铺跟进、逐次外呼、标签待核对三种视图查看。支持员工、状态、工单号/店铺ID/备注搜索。展开“查看工单”后可直达天润。每页30条，翻页不截断总量。

全员监控仅本机或已登录管理员可见；普通内网访客不开放此汇总接口。保留原员工卡点功能和员工权限。
